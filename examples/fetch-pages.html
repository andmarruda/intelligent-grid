Pages with fetch, keeping the rows already loaded

Scroll down: each page is one fetch('/api/orders?offset=…&limit=100') to the demo backend (npm run demo, 100 000 orders). Pages add to the grid: scrolling back up does not ask the server again, and edits on loaded rows stay while more pages arrive. With serverSide: true sort, column filters and search go to the server as JSON (where is a SorlaDB find() query the server runs as is) and the list starts again from the first page; with false they apply to the rows already loaded, without new requests.
